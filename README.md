# 문의 데스크 · Q&A Assistant

독립된 의류 쇼핑몰 고객사이트는 [MORU 실행 안내](MOCK_SHOP.md)를 참고하세요. FAQ 52건·문의 113건을 별도 DB에 넣고, 문의데스크와 HTTP API·서명 웹훅으로 연결합니다.

모의 Q&A 게시판에서 문의 수집 → 답변 초안 → 담당자 승인 → 게시 → 지식 등록 → 조건부 자동 답변을 시험하는 로컬 앱입니다. 실제 사이트에는 연결하거나 게시하지 않습니다.

기존 Q&A 답변과 서비스 사용 중 누적된 답변은 운영자 승인 후 새로운 문의의 검색 근거로 재사용합니다. 원본 문의나 답변이 바뀌면 관련 지식과 자동 사용을 중단하고 다시 승인받습니다.

## 실행

1. Windows에서 Python 3.12 이상을 준비합니다. 개발 검증은 Python 3.14에서 수행했습니다.
2. 처음 설치한 경우에만 이 폴더의 PowerShell에서 **`.\start.bat --init-admin`**을 실행해 관리자 아이디와 비밀번호(10~128자)를 등록합니다. 필요한 패키지도 설치하며 비밀번호 입력은 화면에 표시하지 않습니다. 기존 계정이 있으면 이 단계는 생략합니다.
3. **start.bat**를 더블클릭하고 열린 브라우저의 **http://127.0.0.1:8765**에서 등록한 계정으로 로그인합니다. 웹에서 관리자 계정을 새로 만들 수는 없습니다.
4. 실행 창을 닫으면 수집·답변 처리도 종료됩니다. 백그라운드 예약 작업이나 Windows 서비스는 설치하지 않습니다.

개발 환경에서 직접 실행하려면 다음과 같습니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py --init-admin
.\.venv\Scripts\python.exe run.py
```

기본 데이터 위치는 `%LOCALAPPDATA%\QnaAssistant`입니다. 소스가 있는 OneDrive 폴더와 분리합니다. 같은 데이터 폴더에 두 프로세스를 띄우면 실행 잠금으로 차단합니다. 8765 포트를 사용 중이면 `run.py --port 8767`처럼 바꿀 수 있습니다. 데이터 위치는 `--data-dir` 또는 `QNA_DATA_DIR` 환경변수로 바꿀 수 있습니다.

최초 관리자 등록은 서버를 시작하지 않는 일회성 로컬 명령입니다. `--data-dir`를 지정했다면 등록과 실행에 같은 경로를 사용하세요. 이미 계정이 있으면 재등록·덮어쓰기를 거부합니다. 계정이 없는 상태에서는 일반 실행도 서버를 열지 않으며, `POST /api/setup`은 항상 403으로 차단합니다. 기존 계정·암호·문의 기록은 유지합니다.

## 5분 체험

1. **운영 설정 → 자동 답변**에서 말투와 예외 처리 기준을 포함한 답변 규칙을 먼저 저장합니다.
2. **모의 Q&A → 모의 FAQ 준비**를 누릅니다. 예제 FAQ 20개를 승인하며, 일반 FAQ 18개는 자동 사용을 허용합니다. 첨부 관련 2개는 보수적으로 수동 처리합니다.
3. **운영 설정 → 자동 답변 → 내장 100건 평가**를 실행합니다. 통과한 후 자동 모드를 켜고 설정을 적용합니다.
4. **모의 Q&A**에서 `이용 방법을 알려주세요` 예제의 **같은 질문 새로 등록**을 누른 뒤 저장합니다.
5. 모의 게시판이 저장과 동시에 서명된 웹훅을 보내므로, 새 문의가 즉시 수집되고 승인된 FAQ 답변이 자동 게시됩니다. 웹훅이 누락되거나 지원되지 않는 경우를 위해 30분마다 게시판 전체도 확인합니다. 브라우저를 닫아도 서버 프로그램이 실행 중이면 계속 동작합니다. **문의함으로 수집**은 즉시 전체 확인을 실행하는 수동 버튼입니다.
6. 다른 질문은 **문의함**에서 결론·이유를 입력하고 초안을 생성합니다. 최종 문장을 수정·검토한 후 게시합니다.

`모의 FAQ 준비`로 승인하는 답변은 가상 서비스의 예제입니다. 실제 정책이나 제품 기능으로 해석하지 마세요. 과거 문의와 프로그램 중단 중 들어온 문의는 자동 발송에서 제외합니다.

## 웹훅과 주기 확인

새 문의는 두 경로로 들어오며, 어느 경로로 와도 같은 외부 문의 ID는 한 번만 등록·알림·답변합니다.

| 경로 | 동작 | 용도 |
| --- | --- | --- |
| 웹훅 `POST /api/webhook/board` | 사이트가 문의 등록·수정 시 즉시 알림 | 기본 수집 경로 |
| 주기 확인 (기본 1,800초 = 30분) | 게시판 전체를 다시 조회 | 웹훅 미지원 사이트, 누락·처리 실패한 웹훅 복구 |

웹훅 요청 형식은 다음과 같습니다. 본문에는 문의 번호만 들어가며, 제목·내용은 항상 게시판에서 다시 읽습니다. 본문에 다른 문장을 넣어도 사용하지 않습니다.

```http
POST /api/webhook/board
X-QnA-Timestamp: 1760420000            # 유닉스 초, 서버 시각과 5분 이내
X-QnA-Event-Id: evt-8f2c...            # 전송마다 고유한 8~100자. 재전송 시 같은 값
X-QnA-Signature: sha256=<hex>          # HMAC-SHA256(비밀값, "<timestamp>.<raw body>")

{"event": "question.created", "external_id": "1042"}
```

- 지원 이벤트는 `question.created`, `question.updated`입니다.
- 서명·시각·형식이 틀리면 401/400으로 거부하고 아무것도 저장하지 않습니다. 같은 이벤트 ID는 `{"duplicate": true}`로 응답하고 다시 처리하지 않습니다.
- 서버는 검증 후 바로 202로 응답하고, 문의 조회·자동 답변은 응답 뒤에 처리합니다. 처리에 실패한 웹훅은 재시도하지 않고 다음 주기 확인이 수집합니다.
- 서명 비밀값은 설치 시 자동 생성되어 암호화 저장됩니다. **운영 설정 → 연결 · AI → 웹훅 수신**에서 재발급할 수 있으며 새 값은 한 번만 표시됩니다.
- 모의 게시판은 등록·수정 때 같은 형식의 웹훅을 스스로 서명해 보냅니다. **장애 시험 설정 → 웹훅 누락**을 켜면 웹훅 없이 주기 확인으로만 수집되는 것을 시험할 수 있습니다.
- 이 앱은 `127.0.0.1`에서만 열립니다. 실제 사이트의 웹훅을 받으려면 HTTPS 공개 주소와 호스트 허용 설정이 필요하며, 배포 단계에서 추가합니다.
- 4시간 기본값으로 저장된 기존 설치본은 처음 실행할 때 30분으로 바뀝니다. 직접 다른 값으로 바꾼 경우에는 유지합니다.

## 모의 검색과 실제 AI

| 설정 | 검색 | 답변 초안 | 비용 |
| --- | --- | --- | --- |
| API 키 없음 — 기본 | 문자 특징을 숫자로 바꾼 로컬 검색 | 입력한 결론·이유에 인사말을 붙이는 템플릿 | 외부 API 비용 없음 |
| 운영 설정에서 OpenAI 키 저장 | `text-embedding-3-small` 임베딩 | `gpt-4.1-mini` Responses API | 제공자 API 사용량에 따라 과금 |

모의 템플릿은 생성형 AI의 답변 품질을 검증하지 않습니다. API 키가 설정된 후 실패하면 모의 결과로 조용히 대체하지 않고 오류를 표시합니다. 수동 초안 저장·수동 게시 기능은 계속 사용할 수 있습니다. 환경변수에 API 키가 있어도 기본 모드에서는 자동으로 사용하지 않습니다.

현재 자동 발송은 **승인 FAQ의 질문과 정규화 후 정확히 일치한 경우**에만 원문 답변을 재사용합니다. 공백·문장부호 차이는 허용합니다. 의미가 비슷하지만 다른 문장의 자동 판단은 실제 서비스 자료로 보정한 후 추가할 작업입니다. 검색 점수는 정확도나 정답 확률이 아닙니다.

키·SMTP 암호는 암호화하여 저장하며 Windows DPAPI로 보호한 마스터 키와 분리합니다. 저장한 비밀값을 화면으로 다시 보내지 않습니다. `.pkl`은 HMAC 인증 후 제한된 형식으로만 읽고, 손상된 경우 벡터 DB에서 다시 생성합니다. 외부 pickle 업로드는 지원하지 않습니다.

## 지식과 권한

- 최초 수집한 답변은 지식 **후보**입니다. 관리자가 내용을 검토해 활성화해야 검색에 사용됩니다. 유효기간 기본값은 90일입니다.
- 관리자: 지식 승인·자동 사용 설정, 자동 모드, API·메일·계정·백업 관리.
- 답변 규칙에는 말투, 예외 처리 기준, 금지 표현, 필수 안내, 자동 답변 금지 주제를 설정합니다. 규칙이 없으면 평가와 자동 모드를 사용할 수 없습니다.
- CS: 문의 열람, 초안 작성·수동 게시, 지식 후보 등록. 활성 계정은 최대 5개입니다.
- 수동 게시 시 지식 후보 등록을 선택할 수 있습니다. 자동 답변은 이력만 남기며 스스로 새 지식으로 승격하지 않습니다.
- 지식 또는 답변 규칙의 변경은 관련 초안을 다시 검토하도록 만들고 자동 모드·평가를 무효화합니다. 게시 기록에는 적용한 규칙 버전과 사람 확인 여부가 남습니다.
- 문의 또는 초안을 다른 작업자가 수정하면 버전 검사로 이전 화면의 저장·승인을 차단합니다.
- 완료된 답변의 **게시 당시 근거**에는 게시할 때 저장한 답변 내용·출처·버전을 표시합니다. 지식이 나중에 수정·만료·삭제되어도 이 사본을 사용하고 현재 검색은 다시 실행하지 않습니다. 근거를 저장하지 않은 옛 기록이나 외부 담당자의 답변은 근거 미기록으로 표시합니다. 작성 중인 문의에는 현재 참고 지식을 보여줍니다.

## 모의 장애 시험

**모의 Q&A → 장애 시험 설정**에서 연결 끊김·인증 실패·게시 후 응답 유실을 켤 수 있습니다. 시험 후 체크를 해제하세요.

게시 후 응답이 유실되면 문의가 **게시 확인 필요** 상태가 됩니다. **게시 결과 확인**으로 모의 게시판을 대조하며, 같은 답변을 무조건 다시 보내지 않습니다. 다른 담당자의 외부 답변이나 문의 수정도 감지합니다.

## 이메일·예산

SMTP 설정은 선택입니다. 미설정이어도 앱 내 신규 문의 알림은 저장됩니다. 이메일에는 문의 번호만 포함합니다. 포트 587은 STARTTLS, 465는 SSL을 사용합니다. 앱의 **시험 메일 보내기**는 설정한 주소에 실제 메일을 보내는 버튼입니다.

메일 연결 실패는 1·5·15분 뒤 재시도하며, DATA 단계 이후 결과가 불명확하면 확인 필요로 남깁니다. 이메일의 정확히 한 번 배달까지 보장하지 않습니다.

기본 월 AI 예산은 30,000원입니다. 호출 전 보수적으로 비용을 예약하고 응답의 사용 토큰으로 정산합니다. 추정 단가는 입력 0.002원/토큰·출력 0.01원/토큰·임베딩 0.0001원/토큰이며 **공식 청구 단가가 아닙니다**. 제공자 가격·환율에 따라 관리자 API의 `input_token_krw`, `output_token_krw`, `embedding_token_krw`를 조정할 수 있습니다. 불명확한 실패는 예약 비용을 유지합니다. 과금 한도 보장이 아닌 앱의 보수적 호출 제한입니다.

## 백업·복구·삭제

**운영 설정 → 백업·복구**에서 암호화 백업을 만듭니다. 실행 중 하루 한 번 자동 백업도 생성하며 7일보다 오래된 백업은 정리합니다. DB는 SQLite 백업 API로 복사합니다.

복구 전 현재 데이터를 자동 백업합니다. 복구 후 현재 사용자 계정·누적 사용량·삭제 기록·웹훅 비밀값과 수신 기록을 유지하고 자동 모드를 끄며 모든 세션을 종료합니다. 예전 백업도 웹훅 테이블과 기본 설정을 이전합니다. 다시 로그인해야 합니다. 캐시는 재구성되며 API 검색 모델로 전환하면 필요한 자료의 임베딩 비용이 발생할 수 있습니다.

`master-key.dpapi`는 같은 Windows 사용자 환경에 연결됩니다. 이 파일이나 Windows 사용자 복호화 권한을 잃으면 백업·저장 비밀값을 복구할 수 없습니다. 다른 PC로의 키 이전 기능은 포함하지 않습니다.

완료된 문의는 90일, 감사 메타데이터는 180일 후 일일 정리 대상입니다. 수집 문의 삭제 시 앱이 소유한 모의 원문·관련 지식도 삭제합니다. 삭제 기록은 백업 복구 후에도 적용합니다. 실제 사이트의 삭제 정책은 사이트 연결을 만들 때 별도로 정해야 합니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check static/app.js
```

테스트는 임시 폴더와 모의 게시판을 사용합니다. 실제 OpenAI API나 메일 서버에 접속하지 않습니다. 자세한 측정 결과와 아직 수행하지 않은 검증은 [IMPLEMENTATION.md](IMPLEMENTATION.md), 검색 성능·합성 평가 수치는 [verification.json](verification.json)에 있습니다.

## 파일 구성

- `app.py`, `run.py`: HTTP API·권한·세션·웹훅 서명 검증·주기 실행·메일·예산·백업·실행 잠금.
- `engine.py`, `demo_data.py`: SQLite 상태·모의 게시판·웹훅/주기 수집 공통 처리·중복 방지·승인·자동 판단·평가 자료.
- `rag.py`, `security.py`: 검색·선택적 AI·캐시·암호화·비밀번호 해시.
- `static/`: 한국어 업무 화면. 외부 CDN 없이 동작합니다.

팀 저장소는 https://github.com/lls0312200-ai/qna-assistant 이며 비공개입니다. 팀원 작업은 `dev`에서 분기하고 `dev`로 통합합니다. `master` 반영은 프로젝트 소유자가 별도로 검토합니다. 새 저장소를 만들지 말고 기존 저장소를 복제하세요.

```powershell
git clone https://github.com/lls0312200-ai/qna-assistant.git
cd qna-assistant
git switch dev
```

사이트가 만들어지면 메인·Q&A URL, 인증 방식, 문의 고유 ID, 조회·답변 API 또는 실제 화면 구조를 기준으로 연결 모듈을 추가합니다. 이번 버전은 URL을 임의로 방문하거나 실제 사이트 연결 성공으로 표시하지 않습니다.
