# Internal implementation contract

Local FastAPI + SQLite application. Python modules at project root. No framework frontend. APIs return JSON, errors as {detail: Korean message}. Mutation routes require authenticated session + X-CSRF-Token header except /api/login and the signed /api/webhook/board endpoint (Origin/Host checks still apply). /api/setup is permanently denied with 403. UI gets csrf from /api/me. app.py owns authentication, scheduler, email, backups, HTTP. engine.py owns SQLite business tables, connectors, workflow, audit. rag.py owns search/index/AI operations. security.py owns password and secret protection.

## Engine API for app.py

Engine(data_dir: pathlib.Path, ai=None). Exposes .db_path, .lock (threading.RLock), .connect() SQLite connection row_factory Row; callers close connections. Tables settings(id=1,data TEXT JSON), audit(id,actor,action,target,detail,created_at), notifications(id,question_id,kind,status,attempts,next_attempt,last_error,created_at) are available. App may create users/sessions tables in same DB. Engine uses timestamps UTC ISO strings. Settings contain mode=demo, main_url, qna_url, poll_seconds=1800 (fallback poll; legacy 14400 default migrated once), webhook_enabled=true, last_webhook, webhook_status, auto_enabled=false, allowed_categories=[usage,hours,policy], reply_rules, rules_version, last_sync, connection_status, evaluation_passed=false, budget_krw=30000, smtp_host, smtp_port=587, smtp_user, smtp_from, smtp_to, smtp_tls=true. Secret values handled in app.py, never returned from settings. reply_rules requires tone and exception_policy and may include forbidden_phrases, required_phrases, and blocked_topics. Rules must be saved before evaluation or automation. A rules change disables evaluation/automation and invalidates pending drafts.

Public methods: settings()->dict; update_settings(data,actor)->dict; dashboard()->dict; list_questions(status='',search='')->list[dict]; question(id)->dict; sync(actor='system', recovery=False)->dict; connection_test(actor)->dict; save_draft(id, conclusion, reason, draft, actor)->dict; generate_draft(id,conclusion,reason,actor)->dict; post_answer(id,actor,auto=False,knowledge_candidate=False)->dict; reconcile(id,actor)->dict; list_knowledge()->list[dict]; save_knowledge(data,actor,is_admin)->dict; delete_knowledge(id,actor)->None; search_knowledge(query)->list[dict]; evaluate(actor)->dict; auto_process(actor='system',dry_run=False)->dict; audit_rows()->list[dict]; demo_list()->list[dict]; demo_create(title,body,category='usage')->dict; demo_update(id,data)->dict; delete_question(id,actor)->None. engine methods raise ValueError for invalid operations; app converts to 400. Not found LookupError=>404.

Dashboard: counts {review,draft,posted,confirm}, connection_status,last_sync,auto_enabled,knowledge_active,notifications,list recent questions, evaluation, mode. Question: id,external_id,title,body,category,status (review,draft,sending,confirm,posted,external), baseline bool, version, conclusion,reason,draft,final_answer,decision_reason,created_at,updated_at,external_answer_id, sources list. Detail also includes matches list. Knowledge: id,question,answer,category,status(candidate,active,inactive),version,auto_allowed bool,valid_until ISO,source,approved_by,updated_at. Demo question fields id,title,body,category,version,answer,answer_id; demo_update supports simulated faults fail_auth, timeout_after_post, offline (global mode), plus body edits and external answer. Do not require demo credentials.

Completed answer details never rerun search. For posted answers, sources is the saved publication snapshot (id, version, question, answer, source, score, optional category), matches=[], search_error=null. Publication/reconciliation copies the outbox snapshot to questions.sources. For external answers, sources=[] and matches=[]: an old local draft cannot be attributed to someone else's reply. Missing historical evidence remains empty rather than being reconstructed from current knowledge. Unfinished inquiries continue to return current matches.

## RAG/security interfaces

RAG(data_dir:Path, secret_key:bytes, ai=None). build(records:list[dict])->None; search(query,records,limit=5)->list[dict], adds score float. Only active and unexpired records; HMAC authenticated pkl cache. offline lexical hashed vectors explicitly demo search, genuine OpenAI vectors when ai configured; no silent fallback for configured paid API errors. should_auto(question:dict,matches:list,settings:dict)->(bool,reason,match_or_none). Auto matching conservative: category allowlist, exclusions, conflict/margin, high confidence or normalized exact. Evaluation may use exact supported demo FAQs but must disclose synthetic checks.

AIClient(api_key, budget_callback=None, model='gpt-4.1-mini',embedding_model='text-embedding-3-small'). embed(texts)->list[list[float]]; draft(question,conclusion,reason,sources)->str. budget_callback(stage,kind,usage:dict): reserve before calls using conservative input estimate + max output, settle after; abort errors released only known unbilled. Standard functions redact(text)->str, blocked_reason(text)->str, normalize(text)->str. Security functions hash_password(password)->str, verify_password(password,encoded)->bool; load_master_key(data_dir)->bytes; encrypt_secret(value,key)->str; decrypt_secret(value,key)->str. Master key protected by Windows DPAPI (portable dev fallback file chmod600, clearly documented). No external unpickle.

## HTTP API for frontend

GET /api/me => {setup_required:bool, user:{id,username,role}|null,csrf:string|null}; POST /api/setup always returns 403 and never creates an account or session; POST /api/login {username,password}; POST /api/logout. Login returns the me shape. First admin creation is server-local only: run.py --init-admin prompts for credentials without starting HTTP, calls Runtime.initialize_admin, rejects existing users, and uses the same data directory and process lock as normal startup. Runtime.setup_required returns whether the users table is empty. Normal run.py refuses to serve an uninitialized database. The uninitialized UI shows a service-not-ready notice and no registration form.
GET /api/dashboard; GET /api/questions?status=&search=; GET /api/questions/{id}; POST /api/questions/{id}/draft {conclusion,reason,draft?,generate:bool,expected_version:int}; POST /api/questions/{id}/post {knowledge_candidate:bool,expected_revision:int}; draft_revision returned by save must match on post (409 on stale versions). POST /api/questions/{id}/reconcile; DELETE /api/questions/{id} admin.
GET /api/knowledge; POST /api/knowledge {id?,question,answer,category,status,auto_allowed,valid_until,source}; DELETE /api/knowledge/{id} admin; GET /api/search?q=.
GET /api/settings => settings plus api_configured, smtp_configured, data_dir, mode and external_unavailable_reason. POST /api/settings => editable settings + optional api_key,smtp_password (blank preserves existing); POST /api/connection/test; POST /api/sync; POST /api/webhook/board (no session/CSRF; HMAC-SHA256 X-QnA-Signature over "<X-QnA-Timestamp>.<body>", 300s window, X-QnA-Event-Id dedupe, body {event: question.created|question.updated, external_id}; 202 {accepted,duplicate}; content always re-read from the board); POST /api/webhook/secret admin => {secret,path} shown once; POST /api/evaluate; POST /api/automation/run {dry_run:bool}. Settings/evaluate/automation admin only.
GET /api/audit; GET /api/notifications; POST /api/notifications/test admin; GET /api/users admin => list; POST /api/users {username,password,role} admin; PATCH /api/users/{id} {active:bool} admin; POST /api/backup admin => {filename}; GET /api/backups admin=>list; POST /api/restore {filename} admin, safe basename only + automatic pre-restore backup, expires sessions and auto mode disabled.
GET /api/demo; POST /api/demo {title,body,category}; PATCH /api/demo/{id} {body?,answer?}; POST /api/demo/fault {name:offline|auth|timeout_after_post|webhook_drop,value:bool} admin. Demo create/edit sends a signed webhook unless webhook_drop is on. All demo actions authenticated and demo-only. Actual website unsupported pending adapter: never fabricate live connection success.

## UI

Review-only MORU drafts: `GET /api/reference-drafts` (authenticated) returns availability, API configuration, pending count and job progress. `POST /api/reference-drafts` (admin + CSRF) starts one process-local worker and returns immediately; repeated starts while running return the existing job. It imports published FAQ question/answer/conditions as active manual-draft evidence with `auto_allowed=0`, skips inactive/deleted knowledge and all existing operator input, then calls `AIClient.suggest`. That method returns validated JSON `{draft,source_ids,needs_operator_decision,review_notes}` and uses only supplied source IDs; uncited text is discarded and held for review. Provider errors stop the run without removing saved drafts. No posting or email API is invoked.

Suggested source snapshots include `reference_draft=true` and `requires_decision`. Selected evidence is preserved when saving a draft; a required operator decision blocks posting until conclusion/reason are saved. Current harness checks and explicit human publication remain in force. The UI shows job progress without rerendering the answer form. `run.py --prepare-drafts` starts this worker on local launch; the default launcher does not automatically generate drafts for incoming webhooks.

static/index.html, app.js, style.css. Korean, navy/white, clear demo/real status, setup/login, sidebar dashboard/questions/knowledge/settings/audit/demo. App API envelopes lists directly; dashboard/questions detail above. Render user text using textContent not innerHTML. Button state, error toast, keyboard labels, mobile layout, 15s dashboard refresh (do not overwrite input edits). No external assets/CDN.
